# Spillwave UI Guard — Cursor / Codex Instructions

## UI Development Rules

- **Wireframe first**: Before implementing any non-trivial UI change, create or update a wireframe under `wireframes/` that includes goal, layout, key elements, states, and acceptance criteria.
- **Adversarial review required**: After implementation, perform (or request) an adversarial review that checks the running app against those acceptance criteria. Do not mark the work done without a PASS.
- **Builder ≠ Critic**: Prefer a separate review pass rather than self-approving your own UI changes.
- **Visual baselines**: Update screenshot baselines only after intentional visual changes are confirmed.
- **Standards**: Follow the conventions defined by the Spillwave UI Guard skills (especially `ui-standards`).

These rules apply to all Spillwave UI repositories that have installed this plugin.
