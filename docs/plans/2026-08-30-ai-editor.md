# AI editor: selection, /ai, preview

## Context

All AI in Motion is one-shot whole-document replace with no preview (Refine
sends the entire note through `claude -p` and `setContent`s the result). The
slash menu can only insert atom nodes. `llmClient.ts` already solves the
webview-can't-spawn problem.

This epic makes Motion an AI editor in the old-Notion sense: three entry
points (selection bubble, `/ai` at the cursor, page-level Refine) feeding
one pipeline with preview-before-commit and packed document context.

Phase 1 stays on the existing CLI transport. Streaming, tool use, tables,
and dictation are later tasks on this epic — do not build them in the first
slice.

## Design decisions

- One pipeline: `buildAiContext` + one LLM call + a pending preview.
  Apply accepted edits as a single ProseMirror transaction so ⌘Z undoes the
  whole AI op.
- Never silently mutate. Replace / Insert below / Try again / Discard.
- Context is a pure function over title + full text + selection + a rolling
  per-document log of prior AI ops. Unit-tested. No Tiptap in the tests.
- `/ai` is the first slash command that is not an atom-node insert.
- Phase 1 uses `callLLMFromUI` (existing `/api/llm` + `run_llm_cli`). Do not
  add a Bun sidecar or Anthropic SDK yet — that is the fsCore lesson, but it
  belongs with streaming and tools.
- Tables, DocCommands/tool loop, and dictation are sequenced after this
  slice. Motion still has no Tiptap table extension.

## Tasks

- [ ] (P1) Wireframes for Ask AI bubble and pending preview
  UI Guard: selection menu, /ai prompt, preview panel (Replace / Insert
  below / Try again / Discard), Refine routed through the same panel.
  Empty / working / error states. Markdown mode: Refine only (no bubble,
  no slash).

- [ ] (P1) buildAiContext, canned prompts, session log, unwrap reply
  Pure TS. Budget-truncated surrounding text, title, prior ops. Canned
  rewrite/tighten/expand/grammar/continue. Strip a wrapping markdown fence
  from the model reply. bun test src.

- [ ] (P1) Selection bubble, /ai, preview panel on the CLI transport
  Floating Ask AI on a non-empty WYSIWYG selection. /ai opens a prompt at
  the cursor (slash command with a non-insert action). Preview before
  commit; one ProseMirror transaction on accept. E2E stubs /api/llm.

- [ ] (P1) Route Refine through the same pipeline
  Toolbar Refine is document-scoped Ask AI (no Insert below). Failure
  lands in the preview error state, not window.alert.

- [ ] (P2) Shared TS AI service: stream, per-doc session, prompt cache
  Anthropic SDK behind /api/ai/*. Same module in both runtimes (sidecar
  later, not a second Rust loop). Refine and Ask AI move onto it.

- [ ] (P2) Tiptap tables + markdown round-trip
  Independently valuable. Prerequisite for table tools. Pipe tables
  currently render as plain text.

- [ ] (P2) DocCommands registry and tool-use loop
  replace_range, insert_after_block, table_add_row, table_update_cell.
  Preview list of edits. Slash, AI tools, and later voice dispatch here.

- [ ] (P3) Dictation last
  Depends on DocCommands (and tables, for "new table"). Confirm Groq
  Whisper vs Grok before building. WKWebView has no SpeechRecognition;
  need mic entitlement + STT backend. macOS system dictation is the
  free stopgap.
