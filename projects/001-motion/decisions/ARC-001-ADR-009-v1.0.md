## 3. Context and problem statement

### 3.1 Problem description

Dataset, ImageGen, and DiagramGen blocks each had an inline copy of a `key: value` parser. The welcome document saved an unset diagram as `content: null`, which parsed to the string `"null"`. Every cold page load then called `mermaid.render()` with it and logged an error.

**Problem statement as a question**: How many parsers for block attributes does Motion keep?

### 3.2 Why this decision is needed

- **Business context**: BR-002 needs blocks to survive save and reload.
- **Technical context**: FR-015 (keep blocks through save and reload). NFR-I-003 (data portability).
- **Regulatory context**: None. Motion is not a regulated service.

### 3.3 Supporting links

- **Requirements**: BR-002, FR-014, FR-015, NFR-I-003
- **Design doc**: section 6.9
- **Related ADRs**: None

## 5. Considered options

The options come from the design doc and from the code history. This record does not invent alternatives that nobody considered.

### Option 1: One shared `parseBlockAttrs()` (chosen)

**Description**: `blockAttrs.ts` maps the sentinels `"null"` and `"undefined"` to an empty string and keeps colons inside values.

**Wardley evolution stage**: Custom

#### Good (pros)

- The `"null"` bug has one fix.
- Unit tests pin the regression.

#### Bad (cons)

- Line-oriented. A value with a newline cannot round-trip (B7).

#### Cost analysis

- **CAPEX**: Not recorded. Motion has no budget (ARC-001-REQ). The cost is maintainer and agent time.
- **Relative effort**: Low.

### Option 2: Fix each inline copy

**Description**: Patch the three copies.

**Wardley evolution stage**: Custom

#### Good (pros)

- No new module.

#### Bad (cons)

- "Fixing that in one copy would have left the other two."

#### Cost analysis

- **CAPEX**: Not recorded. Motion has no budget (ARC-001-REQ). The cost is maintainer and agent time.
- **Relative effort**: Low.

### Option 3: Do nothing (baseline)

**Description**: Keep the state before this decision.

#### Good

- No new work.

#### Bad

- Each cold load logs `UnknownDiagramError`, and the E2E gate fails.

#### Cost analysis

- **CAPEX**: None.
- **Relative effort**: None now. The cost appears as defects later.

## 6. Decision outcome

### 6.1 Chosen option

**One shared `parseBlockAttrs()`**

### 6.2 Y-statement

> In the context of three block types that store attributes as text,
> facing the same parser bug in three copies,
> we decided for one shared parser with empty sentinels,
> to achieve one fix for each edge case,
> accepting no multi-line values.

### 6.3 Justification

- The regression is pinned in `blockAttrs.test.ts`.

---

## 7. Consequences

### 7.1 Positive consequences

- No `"null"` render error on cold load.

### 7.2 Negative consequences (accepted trade-offs)

- Multi-line values cannot round-trip (B7). Mitigation: tracked with the block round-trip work.

### 7.3 Neutral consequences

- A new block type must call `parseBlockAttrs()`.

### 7.4 Risks and mitigations
