## 3. Context and problem statement

### 3.1 Problem description

Each filesystem operation must stay inside the workspace folder. A string-prefix check fails for a sibling folder: for a workspace at `/x/ws`, the string `/x/ws-evil/planted.md` starts with `/x/ws`. A symlinked parent folder can also let a new file escape if the check runs before the path resolves.

**Problem statement as a question**: How do both cores decide that a path is inside the workspace?

### 3.2 Why this decision is needed

- **Business context**: BR-001 needs the workspace to be the only place that Motion writes.
- **Technical context**: NFR-SEC-002 needs component-aware containment after symlink resolution, in both cores.
- **Regulatory context**: None. Motion is not a regulated service.

### 3.3 Supporting links

- **Requirements**: BR-001, FR-009, NFR-SEC-002
- **Design doc**: section 6.2
- **Related ADRs**: ADR-001, ADR-007

## 5. Considered options

The options come from the design doc and from the code history. This record does not invent alternatives that nobody considered.

### Option 1: Resolve the path, then compare components (chosen)

**Description**: TypeScript computes `path.relative(root, candidate)` and rejects a result that starts with `..` or is absolute. Rust uses `Path::starts_with`, which compares components. A path that does not exist yet resolves its parent first.

**Wardley evolution stage**: Custom

#### Good (pros)

- Rejects same-prefix siblings and escaping symlinks.
- The root itself counts as inside, which top-level notes need.

#### Bad (cons)

- The Rust call looks like the unsafe string check. A doc comment must explain it.

#### Cost analysis

- **CAPEX**: Not recorded. Motion has no budget (ARC-001-REQ). The cost is maintainer and agent time.
- **Relative effort**: Low.

### Option 2: String prefix check after resolution

**Description**: `candidate.startsWith(root)` on resolved strings.

**Wardley evolution stage**: Custom

#### Good (pros)

- One line of code.

#### Bad (cons)

- Admits `/x/ws-evil` for `/x/ws`.

#### Cost analysis

- **CAPEX**: Not recorded. Motion has no budget (ARC-001-REQ). The cost is maintainer and agent time.
- **Relative effort**: Low.

### Option 3: Rely on the platform sandbox or plugin scopes only

**Description**: Use the scope settings of the Tauri filesystem plugin.

**Wardley evolution stage**: Custom

#### Good (pros)

- No custom code in desktop mode.

#### Bad (cons)

- Does not cover browser mode.
- Scope rules are not the workspace mechanism and are not contract-tested.

#### Cost analysis

- **CAPEX**: Not recorded. Motion has no budget (ARC-001-REQ). The cost is maintainer and agent time.
- **Relative effort**: Low.

### Option 4: Do nothing (baseline)

**Description**: Keep the state before this decision.

#### Good

- No new work.

#### Bad

- A crafted folder name or symlink can read or write outside the workspace.

#### Cost analysis

- **CAPEX**: None.
- **Relative effort**: None now. The cost appears as defects later.

## 6. Decision outcome

### 6.1 Chosen option

**Resolve the path, then compare components**

### 6.2 Y-statement

> In the context of a workspace jail in two cores,
> facing same-prefix siblings and symlinked parents,
> we decided for resolve-then-compare containment by path component,
> to achieve no escape through any of the four known paths,
> accepting a Rust call that needs a comment to read correctly.

### 6.3 Justification

- The contract plants a `-evil` sibling and escaping symlinks for read and write. Both cores refuse all of them.

---

## 7. Consequences

### 7.1 Positive consequences

- Four escape paths are closed in both cores and pinned by contract cases.

### 7.2 Negative consequences (accepted trade-offs)

- Readers can mistake `Path::starts_with` for a string check. Mitigation: the doc comment on `is_inside_workspace` explains it.

### 7.3 Neutral consequences

- New storage code must call `resolveInWorkspace` or `resolve_in_workspace`, never join paths by hand.

### 7.4 Risks and mitigations

| Risk | Likelihood | Impact | Mitigation | Owner |
|------|------------|--------|------------|-------|
| A new code path joins user input to the root without the core | Low | High | P-3 review gate, refusal test for each new command. | Rick Hightower |
