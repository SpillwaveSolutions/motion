## 3. Context and problem statement

### 3.1 Problem description

Playwright's `requestfailed` event does not fire for HTTP 404 or 500. A 404 was the signature of bug B2, where New Note created a file that the editor could not read. The dev server also answered every unknown path with 200 and the app shell, so a missing note read back as HTML.

**Problem statement as a question**: Which signals must fail an E2E test?

### 3.2 Why this decision is needed

- **Business context**: BR-005 needs the gate to catch real user-facing defects.
- **Technical context**: NFR-M-001 (errors show, the E2E guard turns console errors into failures).
- **Regulatory context**: None. Motion is not a regulated service.

### 3.3 Supporting links

- **Requirements**: BR-005, FR-011, NFR-M-001, NFR-A-003
- **Design doc**: section 6.6
- **Related ADRs**: ADR-005

## 4. Decision drivers (forces)

### 4.1 Technical drivers

- **Catch error status**: A response with status 400 or higher is a failure.
  - Requirements: NFR-M-001
  - Architecture principles: P-17

- **Explicit failures**: A missing resource must return an error status.
  - Requirements: NFR-A-003
  - Architecture principles: P-13

### 4.2 Business drivers

- **No silent defects**: A broken flow must not pass quietly.
  - Requirements: BR-005
  - Stakeholder goals: SD-6, G-2 (ARC-001-STKE-v1.0)

### 4.3 Regulatory and compliance drivers

## 5. Considered options

The options come from the design doc and from the code history. This record does not invent alternatives that nobody considered.

### Option 1: Four automatic listeners plus a server fallback split (chosen)

**Description**: `e2e/fixtures.ts` listens for console errors, page errors, failed requests, and responses with status 400 or higher. The fixture is `auto: true`. The server returns JSON 404 for unknown `/api/*` routes, 404 for file-like paths, and the shell for the rest.

**Wardley evolution stage**: Custom

#### Good (pros)

- A spec cannot forget the gate.
- B2 is now visible to the gate.

#### Bad (cons)

- A test that expects an error must call `PageGuard.allow()` with a specific pattern.

#### Cost analysis

- **CAPEX**: Not recorded. Motion has no budget (ARC-001-REQ). The cost is maintainer and agent time.
- **Relative effort**: Low.

### Option 2: Transport-failure listener only

**Description**: Listen for `requestfailed`.

**Wardley evolution stage**: Custom

#### Good (pros)

- Fewer false failures.

#### Bad (cons)

- Misses 404 and 500.

#### Cost analysis

- **CAPEX**: Not recorded. Motion has no budget (ARC-001-REQ). The cost is maintainer and agent time.
- **Relative effort**: Low.

### Option 3: Do nothing (baseline)

**Description**: Keep the state before this decision.

#### Good

- No new work.

#### Bad

- Bug B2 and similar defects pass the suite.

#### Cost analysis

- **CAPEX**: None.
- **Relative effort**: None now. The cost appears as defects later.

## 6. Decision outcome

### 6.1 Chosen option

**Four automatic listeners plus a server fallback split**

### 6.2 Y-statement

> In the context of an E2E suite that must catch user-facing defects,
> facing error responses that are transport successes,
> we decided for an automatic gate on console errors, page errors, failed requests, and status 400 or higher,
> to achieve no silent 404 or 500,
> accepting an explicit allow for each expected error.

### 6.3 Justification

- The gate proof probe `e2e/guard.proof.capture.spec.ts` shows that the gate bites. Its correct result is 3 failed and 1 passed.

---

## 7. Consequences

### 7.1 Positive consequences

- Zero console errors, zero failed requests, and zero error responses during E2E (Definition of Done item 3).

### 7.2 Negative consequences (accepted trade-offs)

- The browser requests `/favicon.ico` without being asked. Mitigation: the server returns 204.

### 7.3 Neutral consequences

- Warnings are recorded but do not fail a test.

### 7.4 Risks and mitigations

| Risk | Likelihood | Impact | Mitigation | Owner |
|------|------------|--------|------------|-------|
| A broad `allow` pattern disables the gate | Low | High | Review each `allow()` call. A bare `/./` is banned. | Rick Hightower |
