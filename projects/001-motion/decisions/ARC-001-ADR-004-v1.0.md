## 3. Context and problem statement

### 3.1 Problem description

The client bundle runs in a browser tab or in the Tauri webview. `Bun` is undefined in both. Code that called `Bun.spawn` from the client was fixed four times (3ff4285, 21a28f9, 5e995d8, 261c89f). Unit tests did not catch it, because they run inside Bun and mock the boundary.

**Problem statement as a question**: How does client code reach a process or the disk, and how does the build prove that it never calls `Bun` directly?

### 3.2 Why this decision is needed

- **Business context**: BR-004 needs desktop mode to work. A `Bun` call in the client fails only in the webview.
- **Technical context**: NFR-M-004 (verification gate). FR-020, FR-021, and FR-022 need process work from the client.
- **Regulatory context**: None. Motion is not a regulated service.

### 3.3 Supporting links

- **Requirements**: BR-004, BR-005, FR-020, FR-021, FR-022, NFR-M-004

## 5. Considered options

The options come from the design doc and from the code history. This record does not invent alternatives that nobody considered.

### Option 1: Routers plus a static import-graph guard (chosen)

**Description**: `llmClient.ts`, `imageClient.ts`, and the other routers call `invoke()` or `fetch("/api/...")` after `isTauri()`. `scripts/guard-client-bundle.ts` walks imports from `src/main.tsx` and fails on any `Bun.` use. It skips type-only imports and comment lines.

**Wardley evolution stage**: Custom

#### Good (pros)

- Finds dormant code.
- Runs in `verify`, CI, and the pre-commit hook.

#### Bad (cons)

- Each new capability needs a route, an IPC command, and a router entry.

#### Cost analysis

- **CAPEX**: Not recorded. Motion has no budget (ARC-001-REQ). The cost is maintainer and agent time.
- **Relative effort**: Low.

### Option 2: Runtime check only, through the E2E console gate

**Description**: Let the E2E gate catch a `Bun` reference error.

**Wardley evolution stage**: Custom

#### Good (pros)

- No new script.

#### Bad (cons)

- Sees only code that a test runs. The enrichment modules were dead code.

#### Cost analysis

- **CAPEX**: Not recorded. Motion has no budget (ARC-001-REQ). The cost is maintainer and agent time.
- **Relative effort**: Low.

### Option 3: Do nothing (baseline)

**Description**: Keep the state before this decision.

#### Good

- No new work.

#### Bad

- The defect returns a fifth time. Work item 01KYJW5X was the open fifth case.

#### Cost analysis

- **CAPEX**: None.
- **Relative effort**: None now. The cost appears as defects later.

## 6. Decision outcome

### 6.1 Chosen option

**Routers plus a static import-graph guard**

### 6.2 Y-statement

> In the context of one client bundle that runs in two hosts with no `Bun`,
> facing a defect that recurred four times in dormant code,
> we decided for transport routers and a static import-graph guard,
> to achieve a build failure for any `Bun` use in the client,
> accepting a route, a command, and a router for each new capability.

### 6.3 Justification

- A runtime gate observes only code that runs. The dangerous code was dormant.

---

## 7. Consequences

### 7.1 Positive consequences

- No recurrence since the guard. Baseline: 4 fixes. Target: 0 new cases.

### 7.2 Negative consequences (accepted trade-offs)

- More files for each capability. Mitigation: the routers share one shape.

### 7.3 Neutral consequences

- Type-only imports from server modules are allowed, because the build erases them.

### 7.4 Risks and mitigations

| Risk | Likelihood | Impact | Mitigation | Owner |
|------|------------|--------|------------|-------|
| A second entry point skips the guard | Low | High | Add a root for each entry point if the bundle splits. | Rick Hightower |
