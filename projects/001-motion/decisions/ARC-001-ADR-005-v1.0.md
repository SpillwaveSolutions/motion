## 3. Context and problem statement

### 3.1 Problem description

Before this decision, the only CI job checked the work log. It did not install Bun or Rust. A pull request that deleted `src/App.tsx` passed green. Contributors, including AI agents, had no single answer to "is the app OK?"

**Problem statement as a question**: Which command decides that a change is done?

### 3.2 Why this decision is needed

- **Business context**: BR-005 (every feature proven before it ships).
- **Technical context**: NFR-M-004 names the steps of the gate.
- **Regulatory context**: None. Motion is not a regulated service.

### 3.3 Supporting links

- **Requirements**: BR-005, None, NFR-M-004

- **Related ADRs**: ADR-004, ADR-006

## 5. Considered options

The options come from the design doc and from the code history. This record does not invent alternatives that nobody considered.

### Option 1: `bun run verify` plus Rust checks in CI (chosen)

**Description**: `verify` runs `tsc --noEmit`, `guard:client`, `bun test src`, and Playwright in order. CI also runs `cargo test --lib` and clippy with `-D warnings`.

**Wardley evolution stage**: Custom

#### Good (pros)

- One command for contributors and agents.
- E2E runs against the real dev server, so a test run is a real app run.

#### Bad (cons)

- E2E makes the gate slow.
- Rust checks are outside `verify`, because they need a Rust toolchain.

#### Cost analysis

- **CAPEX**: Not recorded. Motion has no budget (ARC-001-REQ). The cost is maintainer and agent time.
- **Relative effort**: Low.

### Option 2: Separate commands with no single gate

**Description**: Each contributor picks the checks.

**Wardley evolution stage**: Custom

#### Good (pros)

- Faster local runs.

#### Bad (cons)

- Nobody knows which checks matter.

#### Cost analysis

- **CAPEX**: Not recorded. Motion has no budget (ARC-001-REQ). The cost is maintainer and agent time.
- **Relative effort**: Low.

### Option 3: Do nothing (baseline)

**Description**: Keep the state before this decision.

#### Good

- No new work.

#### Bad

- A pull request that deletes the main component passes CI.

#### Cost analysis

- **CAPEX**: None.
- **Relative effort**: None now. The cost appears as defects later.

## 6. Decision outcome

### 6.1 Chosen option

**`bun run verify` plus Rust checks in CI**

### 6.2 Y-statement

> In the context of a product that AI agents change often,
> facing no single answer to "is it OK?",
> we decided for one command that runs every check, plus Rust checks in CI,
> to achieve a done state that a person or an agent can prove,
> accepting a slower gate.

### 6.3 Justification

- `CHANGELOG.md` frames the release as "the point at which it became possible to know whether it works."

---

## 7. Consequences

### 7.1 Positive consequences

- CI now fails on a broken build, type error, guard error, unit test, or E2E test.

### 7.2 Negative consequences (accepted trade-offs)

- Branch protection does not require the checks yet (G-3). Until it does, a merge can skip them.

### 7.3 Neutral consequences

- Unit tests must stay scoped to `src`, or Bun tries to run the Playwright specs.

### 7.4 Risks and mitigations

| Risk | Likelihood | Impact | Mitigation | Owner |
|------|------------|--------|------------|-------|
| Shared test state makes the gate fail by file order | Medium | Medium | Restore spies after each test (P-18). In October 2026, `workspaceSynthesis.test.ts` leaked an LLM spy into other files. | Rick Hightower |

## 8. Validation and compliance

### 8.1 How implementation is verified

- `bun run verify`
- CI jobs `typecheck, guards, unit, e2e` and `cargo test + clippy`

The decision is verified when `bun run verify` passes and CI passes `cargo test --lib` and clippy.

### 8.2 Monitoring and observability

Motion has no telemetry (P-1). The tests in 8.1 are the monitor.
